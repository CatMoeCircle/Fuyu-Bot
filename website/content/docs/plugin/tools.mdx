title: 工具与中间件

工具（tool）是「有名字、有 schema、可被别的插件或宿主调用」的能力；中间件（middleware）
是流经更新管线时的洋葱式拦截点。两者的注册都记在**当前插件的作用域**下：
插件卸载（或加载失败）时宿主一次性回滚这批注册。

## 注册工具：只登记元数据

<Callout type="warn">
  本版 ABI **只登记元数据**：`register_tool` 收的是一份 JSON 描述，里面没有函数指针的位置，
  登记出来的工具一律是 `handler: None` 的**声明型工具**。插件无法让宿主回调进自己来执行工具。
</Callout>

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 全局唯一，建议 `插件名.工具名` |
| `version` | string | semver，默认 `0.1.0` |
| `description` | string | 给人看的一句话 |
| `input_schema` | JSON Schema | 描述入参 |
| `output_schema` | JSON Schema | `null` / `{}` 表示不校验 |
| `required_permissions` | string[] | 调用前要过的权限门 |
| `idempotent` | bool | 默认 `false` |
| `timeout_ms` | number | 默认 `30000` |
| `is_async` | bool | 默认 `false` |
| `callable` | bool | **读出时才有**：本进程里有没有可调处理器 |

```rust
let handle = host.register_tool(&json!({
    "name": "demo.echo",
    "version": "0.1.0",
    "description": "把入参原样回出去",
    "input_schema": {
        "type": "object",
        "properties": { "text": { "type": "string" } },
        "required": ["text"]
    },
}).to_string());
```

`handle` 无效（`id == 0`）表示登记被拒（重名、schema 不合法等）。

## 调用工具：走注册表

`call_tool(name, input_json)` 返回**请求号**（和 `td_invoke*` 一样，不是结果）。宿主把它交给
`ToolRegistry::call_tool`，顺序是：

```text
查表 → 权限门 → input_schema 校验 → 处理器 → output_schema 校验
```

本版 ABI 登记的工具没有处理器，所以对**这类**工具调 `call_tool` 只会拿到**无效请求号**
（`id == 0`）——声明型工具的用途是「让它出现在 `list_tools` 里、被别人发现」，不是被真的执行。

`list_tools()` 返回全部工具的元数据 JSON 数组。**宿主线程局部缓冲**：读完即弃，
要留就当场拷走，**不要试图释放它**。

脚本侧的名字不同：Python 是 `host.register_tool(...)`，JS 是 `host.registerTool(...)`，
都只收 `name` / `description` / `input_schema`。

## 中间件：六阶段洋葱

```text
PreUpdate → 解析 @type → PreRoute → InPlugin → 分发监听器 → PostResponse
```

| 阶段 | 数值 | 谁跑它 |
| --- | --- | --- |
| `PreUpdate` | 0 | 收到更新、还没解析 |
| `PreRoute` | 1 | 已解析 `@type`，路由前 |
| `InPlugin` | 2 | 分发给监听器之前；**一条更新只跑一遍** |
| `PostResponse` | 3 | 响应发出之后 |
| `PreToolCall` | 4 | 工具调用之前（**目前没有生产调用方**） |
| `PostToolCall` | 5 | 工具调用之后（同上） |

数值就是 ABI 里的 `stage` 参数，与 `fuyubot-middleware::Stage` 一一对应。

```rust
use fuyubot_plugin_api::Stage;

extern "C-unwind" fn drop_outgoing(
    _user: *mut std::ffi::c_void,
    _stage: u32,
    payload: *const std::ffi::c_char,
) -> i32 {
    let update = unsafe { fuyubot_plugin_api::parse_payload(payload) };
    let outgoing = update
        .pointer("/message/is_outgoing")
        .and_then(|v| v.as_bool())
        .unwrap_or(false);
    if outgoing { 1 } else { 0 }   // 1 = 中断本阶段；0 = 继续往下走
}

// 返回的句柄必须活着：drop 即摘除
let _mw = self.host.use_middleware(Stage::PreRoute, drop_outgoing, std::ptr::null_mut());
```

要点：

- **回调是 `C-unwind` 的** `fn(user_data, stage: u32, payload_json) -> i32`：返回 `0` 继续、**非 0 中断本阶段**。
  中断只影响**本阶段剩下的层**，管线继续走下一阶段（已经改过的负载照样往下传），宿主记一条 warning。
- **中间件一条更新跑一遍，不是每个监听器跑一遍**：`InPlugin` 的产出就是所有监听器看到的版本。
  按监听器各跑一遍的话，第 N 个会看到被改过 N 次的负载。
- 洋葱模型：进入段在「继续往下」之前，退出段在之后。不往下走就是中断。
- Rust 侧注册返回的 `MiddlewareHandle` 也是 `#[must_use]`，drop 即摘除。
- 阶段号非法或回调为空会让 `use_middleware` 直接返回无效句柄（不会静默挂个空层）。
