这是**唯一**的跨语言契约：形状只有 `fuyubot-abi/src/lib.rs` 一份实现，C 头文件
`fuyubot_plugin.h` 由 cbindgen 从它生成（**产物，不是源码**，别手改）。宿主侧所有桥在
`fuyubot-loader/src/runtime.rs`。改 ABI = 改那个文件 + 加版本号。

## 插件必须导出的四个符号

| 符号 | 类型 | 必须吗 | 说明 |
| --- | --- | --- | --- |
| `plugin_init` | `unsafe extern "C" fn(*const HostApiVTable) -> PluginHandle` | **必须** | 校验 VTable、构造状态；`abi_version == 0` = 拒绝加载 |
| `plugin_start` | `unsafe extern "C" fn(PluginHandle, *const c_char) -> i32` | 可选 | 返回 `0` 成功；只登记元数据的插件可以不写 |
| `plugin_stop` | `unsafe extern "C" fn(PluginHandle)` | 可选 | 卸载前调一次 |
| `plugin_free_string` | `unsafe extern "C" fn(*mut c_char)` | **必须** | 释放**插件自己**分配的字符串 |

`PluginHandle` = `{ abi_version: u32, size: u32, context: *mut c_void, name: *const c_char }`；
`is_valid()` 的判据是「`abi_version != 0` **且** `context` 非空」，所以插件的 `context` 不能是 `NULL`。

## HostApiVTable：18 个字段

`version` 在偏移 0、`size` 在 4、`host_ctx` 在 8，其余 15 个是函数指针，全是 `Option<...>`；
总大小 = `2 * size_of::<u32>() + 16 * size_of::<*const c_void>()`，由 `const _` 里的
`offset_of!` / `size_of` 断言钉死。每个函数第一个参数都是 `host: *mut c_void`。

| 字段 | 签名（省掉 `host`） | 说明 |
| --- | --- | --- |
| `on` | `(update_type, filter_json, callback, user_data) -> SubscriptionHandle` | 订阅；`filter_json` 里的 `event_type` 选通道 |
| `off` | `(handle) -> ()` | 退订 |
| `emit` | `(event_type, payload_json) -> i32` | 发事件；对插件而言是 `emit_scoped(自己, …)` |
| `register_tool` | `(descriptor_json) -> ToolHandle` | 只登记元数据 |
| `call_tool` | `(name, input_json) -> RequestId` | 走注册表，不是同步返回结果 |
| `list_tools` | `() -> *const c_char` | 全部工具元数据的 JSON 数组（临时缓冲） |
| `provide_service` | `(name, *const ServiceVTable) -> ServiceHandle` | vtable 必须活到注销为止 |
| `get_service` | `(name) -> *const ServiceVTable` | 没有就是 `NULL` |
| `td_invoke` | `(method_json) -> RequestId` | 完整请求 JSON（含 `@type`） |
| `td_invoke_simplified` | `(method_name, params_json) -> RequestId` | 宿主补 `@type` |
| `td_execute` | `(request_json) -> *const c_char` | **同步**执行不碰网络的方法（`parseTextEntities` 之类），当场返回响应；没接 TDLib 返回 `NULL` |
| `use_middleware` | `(stage: u32, callback, user_data) -> MiddlewareHandle` | 回调非 0 → 中断本阶段 |
| `wait_for_update` | `(filter_json, timeout_ms: u64) -> WaitHandle` | **阻塞**当前线程；`0` = 只看当前 |
| `cancel_wait` | `(handle) -> ()` | 从另一个线程取消等待 |
| `log` | `(level: u32, message) -> ()` | 环形缓冲 256 行；非法 level 按 `Info` |

两条形状上的硬要求：

- **第一个参数总是 `host: *mut c_void`**：裸函数指针没有捕获环境，VTable 里放不了闭包；
  不给显式上下文就只能靠进程级全局，那样一个进程只能有一个宿主、测试也没法并行。
- **每个函数指针字段都是 `Option<...>`**：C 侧传 `NULL` 合法，非 `Option` 字段收到 `NULL` 就是 UB。
  Rust 侧 `HostApi::from_raw` 一次解包校验全部 15 个，之后调用路径上没有 `Option`。

句柄类型（`SubscriptionHandle` / `ToolHandle` / `ServiceHandle` / `MiddlewareHandle` / `RequestId`）
都是 `#[repr(C)]` + 单个 `u64`；`LogLevel` = 1..5，`Stage` = 0..5；
`WaitHandle` = `{ id: u64, matched: u32, _reserved: u32, payload_json: *const c_char }`。

## 内存所有权：三条硬规矩

1. **谁分配谁释放**。插件返回的 `name` 与插件自己分配的任何字符串都由插件持有，宿主**绝不** free。
2. **宿主返回的字符串是线程局部缓冲**（`list_tools`、`get_service`、`WaitHandle::payload_json`），
   **只在下一次调用宿主函数之前有效**。要留就当场拷走，并且**不要试图释放它**——
   VTable 里没有 host 侧的 free 函数，这是设计不是遗漏。
3. **`ServiceMethodFn` 的返回值由提供方持有**，调用方读完即弃。

## 版本协商

| 位置 | 谁比 | 不匹配 |
| --- | --- | --- |
| `ABI_VERSION`（当前 `2`） | 编译期常量，两侧共同引用 | — |
| `HostApiVTable::version` | 插件侧 `HostApi::from_raw` | `VersionMismatch` |
| `HostApiVTable::size` | 同上 | `VTableTooSmall`（老宿主 + 新插件） |
| 某个函数指针是 `NULL` | 同上 | `MissingFunction("<字段名>")` |
| `PluginHandle::abi_version` | 宿主侧 `PluginLoader` | `AbiMismatch`：**拒绝加载** |

<Callout type="warn">
  版本不兼容时宿主**不能**调 `plugin_stop`——那是对一个不认识的 ABI 下手。所以插件在 `init`
  里分配的状态这一版回收不了，进程退出时才由操作系统回收。字段只增不改，新增一律追加在尾部。
</Callout>

```bash
fuyubot-sdk abi-version   # 打印 2
```

## 回调为什么是 `C-unwind`

`EventCallbackFn` 与 `MiddlewareCallbackFn` 都是 `unsafe extern "C-unwind" fn(...)`。
`extern "C"` 边界上逃出去的 panic 会直接 **abort 整个进程**，宿主来不及 `catch_unwind`；
`C-unwind` 允许 unwind 穿过边界，宿主就能接住、记一条日志、继续跑下一条更新。
对 C/C++ 而言两者 ABI 完全一致；C++ 异常同样会穿过这个边界，**请自己在回调内处理完**。

`define_plugin!` 生成的三个导出函数还会把插件代码包在 `catch_unwind` 里——两层都要。
