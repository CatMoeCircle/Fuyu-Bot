仓库有两套**互不替代**的发布资产，tag 前缀不同，别混：

| 资产 | tag | 生产方 | 谁消费 |
| --- | --- | --- | --- |
| TDLib 动态库 `TDLib-<os>-<arch>` | `TDLib-v<版本>` | `build-tdlib.yml` + `.github/scripts/*.sh` | 构建期（`fuyubot-tdlib` 的 loader 表） |
| fuyubot 本体 `fuyubot-<os>-<arch>.zip` | `v<版本>` | `release-bot.yml` | 终端用户下载、解压即跑 |

## TDLib 资产（构建期契约）

消费方是 `crates/fuyubot-tdlib/src/loader/vendored.rs` 的 `ASSETS` 表，生产方是
`.github/workflows/build-tdlib.yml` 的 matrix；`tests/release_assets.rs` 会**读 workflow 双向比对**，
漂了就红。四条硬要求：

1. tag 必须精确是 **`TDLib-v<版本>`**（下载 URL 由 `release_url()` 拼）；
2. 资产名**精确等于** `ASSETS` 表的值，**不带扩展名**，`<os>-<arch>` 用 cargo 口径（`x86_64` / `aarch64`）；
3. 内容必须是 **`.tar.gz`**（`.zip` 会被 `extract_library` 当裸库原样写出，得到坏文件还不报错）；
4. **加平台只动 `ASSETS` 表 + CI matrix，两边同时加**（`macos/x86_64` 故意不在表里：没有那个 runner）。

## fuyubot 本体（用户下载即用）

`release-bot.yml` 在 `v*` tag（或手动 dispatch）上按平台编 `fuyubot-cli` + `fuyubot-sdk-cli`
+ 三个内置插件，**分三份单独打包**：本体（可执行文件 + 该平台的 `tdjson`，从 `TDLib-v<版本>` 那个
Release 取）、内置插件（`plugins/`）、SDK。前两份在 `publish` 里叠成**各平台一个 zip**再挂 Release：

```text
fuyubot-windows-x86_64.zip    fuyubot-windows-x86_64/{fuyubot.exe, tdjson.dll, plugins/, README.txt}
fuyubot-windows-aarch64.zip   fuyubot-windows-aarch64/{fuyubot.exe, tdjson.dll, plugins/, README.txt}
fuyubot-linux-x86_64.zip      fuyubot-linux-x86_64/{fuyubot, libtdjson.so, plugins/, README.txt}
fuyubot-linux-aarch64.zip     fuyubot-linux-aarch64/{fuyubot, libtdjson.so, plugins/, README.txt}
fuyubot-macos-aarch64.zip     fuyubot-macos-aarch64/{fuyubot, libtdjson.dylib, plugins/, README.txt}
fuyubot-sdk-<os>-<arch>.zip   只有 fuyubot-sdk（不需要 tdjson）
```

平台集合与 `ASSETS` 表一致：Windows / Linux 各 x86_64 + aarch64，**macOS 只有 aarch64**。

中间产物（`fuyubot-*.tar.gz` / `fuyubot-plugins-*.tar.gz` / `fuyubot-sdk-*.tar.gz`）只留在 Actions
artifacts 里，**不挂 Release**——它们是构建产物，不是发布形态。

三条契约：资产名与 `ASSETS` 同口径、zip 里保留顶层目录 `<资产名>/`、
**`tdjson` 与可执行文件同级**（靠 loader 优先级 2「可执行文件所在目录」命中）。
zip 只在 `publish`（Linux runner）里生成，Windows runner 的 bash 没有 `zip` 命令。

<Callout type="warn">
  GitHub Actions 在本机验不了。改 workflow 的组包步骤时，把 `Package` 与 `Merge` 两段 bash **原样抠出来在本机跑一次**，
  解压产物验证 `--version` / `init` / `run --replay` / `--no-login --background` 全通——
  这一步是踩过「改了却没验」之后定的规矩。
</Callout>

## 文档站

`website/` 是静态导出（`output: 'export'`），产物 `out/`：

```powershell
cd website
pnpm install
pnpm build        # → website/out/
pnpm preview      # 本地静态服务器预览
```

把 `out/` 交给任意静态托管即可；GitHub Pages 记得 `public/.nojekyll`（`_next/` 以 `_` 开头会被 Jekyll 吞掉），
正式域名在**构建前**设 `NEXT_PUBLIC_SITE_URL`（绝对 URL 是烘进产物的）。

发布前过一遍仓库的提交检查清单（`AGENTS.md`）：文档三份都更新（HANDOFF / pitfalls / ROADMAP）、
`cargo build/test/fmt` 三条绿、没把凭据写进任何文件。
